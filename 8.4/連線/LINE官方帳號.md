# LINE 官方帳號：先算則數，再群發

## 方案（台灣，2026-11-01 起，tw.linebiz.com 官方公告，未稅）
| 方案 | 月費 | 每月免費則數 | 加購 |
|---|---|---|---|
| 輕用量 | 0 | 200 | 不能 |
| 中用量 | 1,000 元 | 3,000 | 不能，要升高用量 |
| 高用量 | 1,400 元 | 6,000 | 第 1–50,000 則每則 0.2 元，之後 0.15 元 |

- **群發一次＝收到的人數則。** 412 位好友群發一次就是 412 則，輕用量不夠。一次最多 3 個對話框，仍算 1 則。
- 不扣則數：一對一聊天、歡迎訊息、自動回應、AI 自動回應、Messaging API 的回覆（Reply）。
- 扣則數：群發、分眾群發，和 API 的 Push、Multicast、Broadcast、Narrowcast。封鎖的人不算。
- 則數照日本時間算：台灣晚上 11 點後送出算隔天；月底最後一天 11 點後群發會算進下個月。
- 後台改方案、加購在「設定 → 帳務」（以後台畫面為準）；付款老闆自己按。

## 三層：先用不花錢的
1. 關鍵字自動回應＋圖文選單（後台原生、免費）：接常見問題。規則先接，沒對到才回營業時間和「老闆會親自回」。
2. 群發和分眾（後台原生）：照下面的核准流程。分眾用標籤（新加入、來過一次、熟客）或後台的受眾——後台用標籤群發有沒有人數門檻還沒實測；好友少、篩不了時只給「少發一次」和「升級」兩個選項。
3. Messaging API（要另外架接收程式，課程工作坊才教）：broadcast（全部好友）、narrowcast（用屬性或受眾篩，官方帳號的目標好友要 100 位以上、最後篩出要 50 位以上）、查剩餘則數（quota、quota/consumption）。金鑰放在接收程式的環境變數，永遠不貼進對話。

## 群發核准流程（〈送出前把關〉C 級）
1. 算：好友數 × 這個月要發幾次；讀後台「訊息則數」已用多少。
2. 核准卡：給哪一群、幾位＝扣幾則、發完剩幾則、完整內容、時間。超過方案：給「縮小到一群」和「升級方案（每月＿元）」兩個選項。
3. 老闆說「發」→ 照原文建立 → 送出前截圖給他看一眼 → 按傳送或預約。改了字重來一次。
4. 送出紀錄：C、日期、對象、人數、則數；發文表記回應和來約。
5. 每月 25 號：剩不到下次群發要的則數，提醒老闆先決定升級或縮小對象。
