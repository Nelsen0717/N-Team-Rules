# 有風數字視覺：設計系統（8.4 草稿）

這份是規格，也是 v2 審查的結果。目標：對數字不熟的店老闆打開就看到三件事：**現在在哪、差多少、下一步做什麼**。
程式在同一個資料夾：四頁 `.tsx`（bot 用的）、`共用段/`（每塊的正本）。店家資料只放第 2 行 `const D=`。
裡面的店都是示範店，不是任何一家真的店。

## 1. 老闆常問的七句話，用哪個模組回答
| 老闆想知道 | 模組 | 在哪一頁 |
|---|---|---|
| 現在走到哪？ | 進度條 Prog | 診斷報告、進度總表 |
| 離目標還差多少？ | 目標環 Ring、方塊「還差幾位」 | 進度總表、記分板 |
| 客人在哪一站掉下去？ | 漏斗 Funnel | 診斷報告（主角）、記分板 |
| 先顧哪一群客人？ | 客人三圈 Rings | 記分板（主角） |
| 六站整體長怎樣？比之前好嗎？ | 六站雷達 Radar | 自介卡、記分板 |
| 有變好嗎？哪裡來的客人？ | 走勢 Trend、柱圖 Cols、條圖 HB | 記分板、進度總表 |
| 下一步做什麼？誰做？ | 下一步 Next、頭像 Face | 診斷報告、記分板、進度總表、自介卡 |

不做：圓餅（三圈已經回答）、儀表盤、文字頭像、會一直動的東西。

## 2. 每頁一個主角
| 頁 | 主角 | 順序 |
|---|---|---|
| 自介卡 | 頭像大卡 | 大卡 → 4 方塊 → 團隊 → 雷達 → 固定節奏 → 三件先問你 → 結尾 |
| 診斷報告 | 漏斗 | 進度條 → 結論 → 4 方塊 → **漏斗** → 先做哪一招 → 第一位客人 → 請哪兩位 → 原話 → 還缺的 |
| 記分板 | 客人三圈 | 4 方塊 → 這兩週先做 → **三圈** → 漏斗 → 雷達 → 走勢 → 管道 → 其他 → 這週看到的 |
| 進度總表 | 目標環 | 4 方塊 → **目標環** → 今天三件 → 每天來問 → 六段 → 團隊 → 等你決定 |

## 3. 顏色
- **綠 `#315E4C`、橘 `#E5622B`，色票不變。** 程式直接用，不靠 `Page palette`。
- 為什麼：目前的 Grok Canvas runtime 裡，`Page` 沒有 `palette`、`lang`，`theme.dataviz` 固定是藍 `#1084FE`、琥珀 `#FF9800`。v2 靠 palette 上色，實際畫出來是藍色；內建的 `LineChart`、`Bars`、`Columns`、`Callout` 也是藍色，所以 8.4 不用它們，改用共用段的 Trend、HB、Cols。
- **深色模式**：`#315E4C` 在黑底對比不到 3:1，畫不清楚。圖上的綠在深色模式改用同色系淺綠 `#7FB79F`（`useT().g`）。綠色大卡是大面積底色，兩種模式都用 `#315E4C`。
- **橘一頁只有一處**，就是這兩週要動的那一個：自介卡＝現在這一步；診斷報告＝漏斗最卡那站；記分板＝三圈的起點；進度總表＝落後時的目標環，沒落後時是今天第一件。其他地方的「最卡」用粗字、深色點，不用橘。
- 字一律用 `theme.text`。不用 `text.tertiary` 寫內容（對比不足 4.5:1）；狀態字用 `successDeep`、`warningDeep`。
- 頭像是貼紙：奶油色底，兩種模式都一樣。設計師的衣服改成紫色，不佔橘。

## 4. 字與數字
- 大卡名字 24、目標環中間 30、方塊數字 26（單位 14）、下一步 20、內文 15、標籤 13、最小 12。SVG 的字換算到手機上也要有 11 以上。
- 數字用等寬數字。單位比數字小，數字本身不斷行。
- 沒資料一律 `null`，畫面寫「還沒有資料」，不畫假 0：雷達的折線會跳過沒資料的站，每天來問的柱圖不畫沒資料的那天。
- 推估寫「約 45,900 元（估計）」、「約 4 位（估計）」。
- 每個數字都有算法和出處：方塊點開看；漏斗、雷達、三圈點一站看；走勢、管道、每天來問、目標環直接寫在圖下面。

## 5. 動態：克制
| 什麼 | 怎麼動 | 備註 |
|---|---|---|
| 主角 | 每頁只有它進場：大卡淡入 400ms；漏斗每條長出 700ms（依序 60ms）；三圈一圈一圈亮 400ms；目標環 800ms | 主角在第一屏外就**捲到才播**（Stage）；8 秒保險，免得永遠看不到內容 |
| 其他模組 | 直接出現 | 不動 |
| 數字跑動 | 500ms，**10 以上才跑，每次打開只跑一次**；點別的地方不會重跑 | Canvas 是沙箱，存不了「看過了」，所以下次打開會再跑一次 |
| 點選 | 團隊卡展開 240ms；A/B 點選放大 200ms | 只回應手指，開頁時不動 |
| 減少動態 | 一條 CSS 全關，數字直接是終值，不留淡入 | |

動畫全放 CSS（`animation … backwards`）：內容的最終狀態就在畫面裡，JS 出問題也不會只看到 0 或空白。

## 6. 手機
- 可點的地方都至少 44×44（`驗收.mjs` 會量）。三圈的環太窄，所以下面多四格可點。
- 漏斗的條會變窄，字不跟著變窄。雷達、三圈的畫布改成 320 寬，手機上幾乎 1:1，不再縮到看不見。
- 方塊最小 136，360px 上一定兩欄。

## 8. D 欄位（第 2 行）
不知道一律 `null`，不填 0。`sample` 真的店填 false。
- **診斷報告**：跟 8.3 完全一樣，看 `8.3/頁面/診斷報告-欄位.md`（建 8.4 時一起帶過來）。
- **自介卡**：跟 8.3 一樣（name、shop、date、img、promise、now、team、beat），多兩欄：`six` 六站 0–3 或 null（從診斷 c 第 7、9、11、13、14、16 題換算，A3 B2 C1 D0）；`sixAt` 出處字。team 多第 5 欄：頭像 data URI，沒有留空會用插畫。
- **記分板**（分析師每週填）：shop、date；day 這期第幾天；goal 兩週成交目標；dealC 這期累計成交；ask／askPrev、deal／dealPrev 這週和上週來問、成交；funnel[5] 詢問、洽談、成交、到店、回流人數；est 哪幾站是估計；score[6] 這週六站 0–3，不到 10 位填 null；base[6] 診斷時六站；cycle 回購週期天數；bands[3] 熟客、開始變少、很久沒來；newAsk 這個月新來問還沒買；weeks [週, 來問, 成交]；ch [管道, 來問, 成交]；ai [有推薦題數, 總題數]；aiDiff 比上週；made、askAll 累計做了幾件、累計來問；note 最多三句。
- **進度總表**（總管每天 9 點填）：shop、date；done 走完幾段；goalNow、goalAll、goalName 兩週目標；day 這期第幾天；now 現在這一步；today 最多三件 [誰, 什麼事, 狀態]；team [職稱, 狀態, 最近成品, 頭像]；wait 等你決定；days 最近 7 天 [日期, 人數]，**總管開門時從客人名單「第一次來問」欄逐位數，沒名單填 null；跟分析師週日的數字不一樣時，以分析師為準**。

## 9. 審查 12 題的答案
1. 太多了。每頁只有主角動，其他直接出現；主角在第一屏外就捲到才播。
2. 只跑一次，縮到 500ms，10 以上才跑。1、2、3 跑起來只是閃一下。
3. 夠。最卡有橘色、粗字、「← 斷在這」三層，不用閃。A/B 脈動拿掉，改成點選時放大。
4. 不留。減少動態全關。
5. 大卡白字約 7:1，留。深色的問題在別處：黑底上的綠、SVG 字、白底小卡；綠改淺綠，其他改用 theme。
6. 認得出，但說客、分析師都是眼鏡分不出來，已換配件：說客對話框、分析師長條、設計師三色點；旁邊永遠有職稱。
7. 會擠，也讀不到。字搬到條外面整行；三圈畫布從 700 改 320，下面加四格可點。
8. 會斷（「12／位」）。數字不斷行，單位變小。
9. 同意；記分板不換主角，「離目標多遠」放方塊和進度總表。
10. 雷達、圓餅沒砍錯。再合併四個：方塊迷你線（下面有完整圖）、團隊細條（＝已到職方塊）、A/B 分頁（象限本身可點）、點看怎麼算的提示（四格一句）。
11. 縮了：動畫改 CSS、去掉重複、沒用的塊不帶。再縮就要砍模組；記分板見第 7 節。
12. 總管每天自己數，只是數列數、不判斷；分析師一週才跑一次，來不及。寫法放規則包第 8 節，不佔範本預算。
